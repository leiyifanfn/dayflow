# DayFlow

DayFlow 是一款 Windows 个人日常管理应用：用清单建立习惯，用周计划安排任务，用日记记录感想，用复盘查看完成情况。桌面猫咪挂件可以直接勾选今天的计划。

本仓库从现有 DayFlow 1.0.0 安装包中恢复源码，并完善为 1.1.1。包含构建配置、测试、数据库迁移和打包脚本；不包含个人日记、账号凭据或 Electron 安装目录中的运行库。

## 功能

- 清单：创建和删除清单及事项，选择颜色和图标，每日打卡。
- 周计划：按天安排任务，拖入整个清单或单个事项，设置周标语。
- 日记：逐项写计划感想；笔记本支持文字、图片和画板；编辑立即存入本地。
- 复盘：离线和游客均可使用，支持 1、4、12、52 周；关联原始清单事项，避免重复统计同一次打卡；未安排的打卡也计入统计。
- 模板库：10 套内置清单，一键加入个人清单。
- 皮肤：36 种配色、7 种猫咪图标。
- 挂件：置顶、拖动、记住位置，查看和勾选当天计划，与主窗口同步。
- 账户：邮箱登录、用户名作为显示名称、邮箱验证码注册及密码重置。
- 数据：按账号隔离本地数据；五个模块完整同步，包含打卡、画板和删除；离线排队、联网重试、版本冲突处理。
- 备份：导出 JSON，兼容旧版备份；导入前校验全部模块，清理不安全 HTML，保留恢复前备份和被舍弃的冲突版本。

## 本地开发

需要 Node.js 22 或 24、npm 和 Git。开发/安装包建议使用 Windows。

```sh
npm ci
npm run dev
```

默认不配置云端即可使用游客模式。云端配置为空时，账户操作会提示尚未配置。

```sh
npm run typecheck
npm test
npm run build
npm run pack
npm run dist
```

- `build` 输出到 `out/`。
- `pack` 输出便携应用目录 `release/win-unpacked/`。
- `dist` 输出 Windows NSIS 安装包到 `release/`。
- 安装包未配置代码签名；如需签名，在构建环境提供自己的签名证书。

## 配置 Supabase

1. 在自己的 Supabase 项目 SQL Editor 中执行 [`001_documents.sql`](supabase/migrations/001_documents.sql)。
2. 把 `.env.example` 复制为 `.env`，填写项目 URL 和公开的 publishable/anon key。
3. 开启 Authentication 的 Email 登录与 **Confirm email**。在注册确认和密码恢复的邮件模板中显示 `{{ .Token }}`，供应用中的验证码输入框使用；SMTP 和邮件发送额度需在 Supabase 中配置。
4. 重新启动开发服务或重新构建安装包。

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_KEY
```

这些值在构建时注入。客户端只能使用公开 key，不能使用 `service_role` key、SMTP 密码或管理员令牌。`.env` 已从 Git 和源码 ZIP 中排除。

数据库启用 RLS，只允许用户读写自己的文档。同步 RPC 使用当前登录用户和版本比较，在行锁内提交修改。

## 升级和已有数据

- 旧安装包仍保留在原目录。本仓库的构建产物另存于 `release/`。
- 初次使用 1.1.1 时，旧版无账号区分的本地数据复制到游客空间；原键保留。不会把游客数据自动上传给新登录账号。
- 要把游客数据转到自己的账户，先在游客模式导出，再登录并导入同一个 JSON 文件。
- 旧版云端使用多张业务表；新版使用 `dayflow_documents`。安装数据库迁移后，可在“皮肤 → 数据同步”点击“导入旧版云端数据”，从当前用户的旧表分页读取并填充本地为空的模块。原业务表不会被删除。已有新版云端数据产生冲突时，需要选择保留版本。
- 日记、周计划、清单、打卡和主题分别是一个同步文档；同一模块在多台设备离线编辑时不自动合并，应用提示“保留本地”或“使用云端”。另一个版本会保留在导出的 `__conflict_backups` 中。
- 数据仍受 Electron 本地存储容量限制；大量内嵌图片可能触及容量上限，应用会提示保存失败。建议定期导出备份。

## 项目结构

```text
src/main/                 Electron 主进程、窗口和托盘
src/preload/              主进程与界面的 IPC 桥接
src/renderer/src/         React 页面、猫咪挂件和状态管理
src/renderer/src/lib/     本地存储、同步、备份、迁移与复盘
packages/shared/src/     日期工具、类型和 Supabase 账户接口
supabase/migrations/     云端文档表、RLS 与同步 RPC
tests/                   同步、复盘、账号隔离与备份测试
scripts/                 源码打包与仓库发布辅助工具
assets/                  应用图标
.github/workflows/       自动测试、构建和安装包产物
```

## 私有源码与公开发行

- 私有源码仓库：`leiyifanfn/dayflow-source`，只供所有者及其授权成员访问。
- 公开发行仓库：`leiyifanfn/dayflow`，只包含下载说明、空结构占位文件和 Release 安装包，不包含项目实现。
- 本次只发布 PC 安装包；Android 安装包以后单独添加。
- 安装包不附带项目的 TypeScript 源文件或 source map；打包的 JavaScript 压缩后存入 ASAR，并开启 Electron 的 ASAR 完整性检查。
- 这些设置降低直接替换应用脚本的便利程度，不保证安装包无法被反编译或修改。发布包目前未配置代码签名。

在本私有仓库中开发后，使用 `git add`、`git commit` 和 `git push` 保存迭代。构建验证通过后，把安装包上传到公开发行仓库的 Release。不得把本仓库源码 ZIP 上传到公开仓库。

`npm run archive` 仅用于你自己的私有源码备份，生成的文件不要公开。发布脚本要求目标工作目录存在 `.distribution-only` 标记，并拒绝上传非空的实现代码。

## 验证范围

本地回归测试覆盖：离线复盘、清单关联和去重、取消/删除的数据上传、网络错误重试队列、并发修改版本冲突、上传期间继续编辑、账号切换、画板同步、备份格式检查及 HTML 清理。

界面操作测试覆盖：游客创建清单和打卡后离线复盘，以及挂件勾选计划后在主窗口查看复盘。数据库 CI 使用 PostgreSQL 16 验证 RLS 账号隔离和过期版本拒绝覆盖。

云端邮箱投递和跨设备实际同步需要配置你自己的 Supabase 项目；测试使用模拟后端，不会登录原安装包的云端服务。
